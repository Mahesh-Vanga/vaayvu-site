Our product

Vaayvu Browser

One browser. Four platforms. Everything built in — no extensions required, no accounts forced, no cloud you don't control.

v0.0.23 · MIT licensed

A quieter browser for macOS, Windows, Android, iOS

Vaayvu uses native web views on each platform — WKWebView, WebView2, Android WebView — wrapped in a shared Rust core. No Electron, no Chromium fork, no bloat.

Rasha Shield (built in)

Local-first ad & tracker blocking. No EasyList, uBlock, or AdGuard rules. Rules compile to bytecode and match on-device — page content never leaves your machine. Strong mode catches same-site ad paths and YouTube ads. Per-site toggle with instant reload.

Spaces

Work, study, and personal tabs stay separated. Each space has its own tabs, pinned pages, and accent color. Switch instantly — no mixing contexts.

Vaayvu Sync (self-hosted)

Your bookmarks and open tabs encrypt locally (AES-GCM, Argon2id keys), transmit to your sync server, decrypt on the other end. No Locathara accounts, no telemetry, no cloud. Single binary you run anywhere.

India Search (optional mode)

Replaces web search with curated, on-device directories for government services, pincodes, IFSC codes, and more. Works offline after download. No query logging. Ask-before-open for external links.

Technology

Built differently from the ground up

We don't fork Chromium and call it a day. Vaayvu uses native web views on each platform — WKWebView, WebView2, Android WebView — wrapped in a shared Rust core for shield, sync, and spaces logic.

Rust core, native shells

Shared business logic in Rust compiled to a dynamic library. Each platform gets a thin native wrapper — Swift on Apple, C++/WinRT on Windows, Kotlin on Android. Smaller binaries, native performance, platform fidelity.

VFD — Vaayvu Filter Definition

Our own rule format compiled to bytecode. Declarative, typed, and verifiable. Rules express "block this domain on these pages" not "match this regex." Enables strong mode, per-site toggles, and instant reload without re-parsing.

End-to-end encrypted sync

Keys derive from your passphrase via Argon2id. Data encrypts with AES-GCM before leaving the device. The sync server stores only ciphertext — it cannot read your bookmarks or tabs.

Style-only extensions

Extensions are CSS packages scoped to origins. No JavaScript execution, no background pages, no permission prompts. You change how a site looks — not how it behaves.

Per-site shield state

Turn shields down for one site — it reloads instantly. Other tabs keep full protection. State persists per-origin, not globally. No "pause everywhere" that leaks your privacy.

Local-first, always

No telemetry backend in shipping builds. No crash reporting to our servers. No update checks that fingerprint you. The browser checks for updates by fetching a static JSON file — no client identity sent.

Philosophy

Why we build this way

The modern web runs on attention extraction. We're building the alternative — software that serves you, not advertisers.

01

Local by default

Computation happens on your device. Rule matching, sync encryption, space management — nothing leaves your machine unless you explicitly configure a sync server.

02

No dark patterns

No nag screens, no forced accounts, no "sign in to sync" walls, no telemetry opt-out buried in settings. The browser works fully without an account.

03

Honest about limitations

We document what doesn't work: no scripted extensions, no DRM video on Linux, iOS build requires your own Apple team. We'd rather you know upfront than discover later.

04

Sustainable, not VC-scale

Locathara is self-funded. We don't need hypergrowth. We need a viable business that can pay developers to maintain this for the next decade. That means small team, low burn, direct relationship with users.

05

Open source, not open core

The browser, shield engine, sync server, and native hosts are all MIT-licensed. No "enterprise features" held back. If you want to fork and build a business on it, go ahead — we'd love to see what you make.

06

Native feel, not Electron

WKWebView on macOS/iOS, WebView2 on Windows, Android WebView on Android. Each platform gets its own text rendering, scrolling physics, and system integration. It's more work — but it feels right.

How we operate

  • Default to native. If the platform provides it, we use it. Web views, keychain, notifications, window management — platform APIs first.
  • Ship the smallest thing that works. No feature flags for unfinished work. No "coming soon" pages. If it's not ready, it doesn't ship.
  • Document the sharp edges. Every limitation, every platform difference, every "why" — written down for users and future contributors.
  • No telemetry without consent. And even then, only local. We don't run a telemetry pipeline and have no plans to.
  • Profit from value, not data. If we ever charge, it'll be for something you'd pay for — not for selling your attention.
