Philosophy

Why we build this way

The modern web runs on attention extraction. We're building the alternative — software that serves you, not advertisers.

Our principles

Six principles that guide every decision

Not marketing values. Engineering constraints we refuse to compromise on.

01

Local by default

Computation happens on your device. Rule matching, sync encryption, space management — nothing leaves your machine unless you explicitly configure a sync server. This isn't a privacy feature; it's the architecture.

What this means in practice

  • Rasha Shield compiles rules to bytecode and matches entirely on-device — zero network requests for filtering
  • Vaayvu Sync encrypts with keys derived from your passphrase via Argon2id before any data leaves the device
  • Spaces, themes, and preferences stored locally in IndexedDB / platform keychain
  • Update checks fetch a static JSON manifest — no client identity, no fingerprinting
  • Crash reports and diagnostics stay local unless you manually share them
02

No dark patterns

No nag screens, no forced accounts, no "sign in to sync" walls, no telemetry opt-out buried in settings. The browser works fully without an account. You download, you use it. That's it.

What we explicitly don't do

  • No "create account to continue" interstitial on first run
  • No "sync is better with an account" nags in the UI
  • No pre-checked "help improve Vaayvu" telemetry consent
  • No feature gating behind authentication
  • No "you're missing out" messaging for non-synced users
  • No automatic cloud backup of anything
03

Honest about limitations

We document what doesn't work: no scripted extensions, no DRM video on Linux, iOS build requires your own Apple team. We'd rather you know upfront than discover later and feel misled.

Current known limitations

  • No scripted extensions: Only CSS-based style packages. No JS APIs, no background scripts, no content scripts.
  • iOS build requires your Apple Developer account: We cannot distribute a signed iOS binary. You build from Xcode with your team.
  • No DRM video (Widevine/PlayReady): Native web views on Linux/macOS/Windows don't expose CDM APIs. Netflix, Prime Video, etc. won't play in HD.
  • No translation API: Platform web views don't expose built-in translation. Use a style extension or external service.
  • Limited PDF editing: Native PDF viewers are read-only. Annotations require external tools.
  • No sync for private windows: By design — private tabs never touch the sync engine.
04

Sustainable, not VC-scale

Locathara is self-funded. We don't need hypergrowth. We need a viable business that can pay developers to maintain this for the next decade. That means small team, low burn, direct relationship with users.

What sustainability looks like for us

  • No investor pressure: No board demanding 10x returns. No "growth at all costs" mandates.
  • Small team, high leverage: Rust core + native shells means one engineer can maintain four platforms.
  • Direct revenue: If we ever charge, it'll be for something you'd pay for — not for selling your attention or data.
  • No pivot risk: We're not building for acquisition. We're building for the next 10+ years.
  • Community alignment: Our incentives match yours. We win when the browser is good enough that you'd recommend it.
05

Open source, not open core

The browser, shield engine, sync server, and native hosts are all MIT-licensed. No "enterprise features" held back. If you want to fork and build a business on it, go ahead — we'd love to see what you make.

What's open (everything)

  • Vaayvu Browser: All platform shells, UI, core logic — github.com/Mahesh-Vanga/vaayvu-site
  • No CLA required: Contributions welcome under MIT. No contributor license agreement that assigns copyright.
06

Native feel, not Electron

WKWebView on macOS/iOS, WebView2 on Windows, Android WebView on Android. Each platform gets its own text rendering, scrolling physics, and system integration. It's more work — but it feels right.

Why native web views matter

  • Text rendering: Each platform's text shaping, hinting, and font fallback — not a compromised cross-platform compromise
  • Scrolling physics: macOS momentum, Windows precision, Android fling — each feels like the OS
  • System integration: Keychain, Credential Manager, Keystore; native notifications; platform auth dialogs
  • Binary size: ~50 MB total across platforms vs ~200 MB+ for Electron
  • Memory: Shared system web view process vs dedicated Chromium per app
  • Security updates: OS updates the web view; we don't ship a browser engine
  • Accessibility: Platform-native accessibility tree, not a custom implementation

Manifesto

We believe the web can be a tool for thought, not a trap for attention.

We believe software should serve the person using it, not the company selling it.

We believe privacy is not a feature you toggle — it's the default architecture you build on.

We believe sustainable businesses are built on trust, not surveillance.

We believe open source means open — not "open core" with the good parts locked away.

We believe native platforms deserve native apps, not web apps in a trench coat.

We're building the quieter web. One browser at a time.
